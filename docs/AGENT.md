# FerrumGate 实施检查

适用范围和仓库级约定见 [根目录 AGENT.md](../AGENT.md)。本文件按改动类型列出需要核验的行为。

| 改动 | 核验 |
|---|---|
| 配置 schema | 空配置、未知字段、重复键、旧示例、边界值、错误候选保留旧快照；新字段注明缺省语义和是否需要重启 |
| 路由与头部 | 未知站点、Host 大小写、端口、非法 authority、路径边界、查询、双向逐跳字段剥离、信任头重建 |
| HTTP 请求或响应体 | 真实连接验证固定长度、chunked、大文件、客户端断开、中途截断；涉及 trailers 或升级时以两端协议测试验收 |
| 监听、调度与退出 | 接入限制、超时阶段、取消、持续连接、进行中操作、异常任务、恢复后状态 |
| 端口映射 | 列表书写顺序、范围展开、单目标复用、重复监听、展开后的会话预算与真实回环目标 |
| 协议升级 | 路由开关、握手证明与子协议、逐跳头、正常 Close、拒绝响应、占用名额、停机与寿命到期、TLS 两跳 |
| TLS 与证书 | 证书链、密钥匹配、SNI、出站主机名、过期、重载、热轮换与重启 |
| 管理与状态变更 | 最小权限和提交版本、审计、并发更新、写入中断、响应丢失后重试及回滚 |
| 外部提供商与系统模块 | 真实请求契约、资源所有权、权限、限速、失败恢复、隔离环境下清理范围 |
| 性能与依赖 | 请求关键路径差异、锁与分配、连接/任务数、依赖 feature、实际负载证据 |

## 实施顺序

1. 通过根 `Cargo.toml` 定位负责的 workspace 成员，阅读上游行为契约及本地入口，确认本次变更依赖哪个已交付阶段。
2. 实现最小完整路径，并为新边界保留一个能捕获回归的测试。能在同一测试里共享启动成本时，保持对用例失败的定位能力。
3. 跑静态检查与实际回环场景。用临时目录、临时端口和自有测试数据，始终回收进程和连接。
4. 更新设计的接口约定与执行清单。记录工具链、平台、命令、退出码和现象。对外部服务的 mock 结果和真实环境结果分别标注。
5. 引入可选模块时，检查默认构建依赖树和显式开启构建，运行真实入口检查启动、禁用、配置与关闭语义。按有价值的组合建立矩阵。

## 评审记录

按范围、契约变化、验证证据和待验证条件组织。变更涉及较高风险的网络或身份边界时，沿数据流复核解析、归一化、策略判断、上游操作和失败返回。部署约定见 [DESIGN.md](DESIGN.md)，阶段命令见 [EXECUTION.md](EXECUTION.md)。
